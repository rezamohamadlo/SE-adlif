# Run VS-MT SSC on another PC

For an existing checkout without active training, obtain the published VS-MT
implementation with `git pull --ff-only`, then use the dry-run and training
commands below. Git does not transfer ignored datasets or baseline checkpoints;
these must already be present or be transferred separately.

The local transfer package captures the original pre-commit implementation
snapshot and includes the existing MT comparison checkpoints:

```text
archive/transfers/vs_mt_ssc_v1_2026-10-31.zip
```

It contains the VS-MT implementation, model registration, SSC config, dedicated
launcher, focused tests, guides, and the existing three MT SSC seed records
including best/last checkpoints and ordinary-inference costs. It does not
contain a virtual environment, raw datasets, caches or current PC3 training.
Packaged source bytes and dataset hashes are listed in
`results/provenance/vs-mt-ssc-transfer-2026-10-31.json` inside the package.

When using that frozen package instead of the published implementation, use a fresh checkout at source commit
`06fd4dca5c78455371df3b39fa4c58f0c9bcccc6`; keep active checkouts untouched.
From the destination parent directory:

```powershell
git clone https://github.com/rezamohamadlo/SE-adlif.git SE-adlif-vs-mt-ssc
Set-Location SE-adlif-vs-mt-ssc
git checkout --detach 06fd4dca5c78455371df3b39fa4c58f0c9bcccc6
```

Copy the ZIP into that checkout, then apply it to this fresh checkout only:

```powershell
Expand-Archive -LiteralPath .\vs_mt_ssc_v1_2026-10-31.zip -DestinationPath . -Force
```

Prepare a separate `.venv` using [the Windows setup guide](../../SETUP_THIRD_PC.md)
and the pinned repository requirements. Do not copy the source PC's `.venv`.
Copy these exact dataset files from the source checkout to identical relative
paths in the new checkout:

```text
data/SSCWrapper/ssc_train.h5
data/SSCWrapper/ssc_valid.h5
data/SSCWrapper/ssc_test.h5
```

They total approximately 3.73 GB (decimal). Previously observed test results
remain disclosed; this experiment must not tune using test accuracy.
Verify the package contents and datasets after preparing the environment:

```powershell
@'
import hashlib, json
from pathlib import Path
m = json.loads(Path('results/provenance/vs-mt-ssc-transfer-2026-10-31.json').read_text())
for r in m['files'] + m['datasets']:
    p = Path(r['path'])
    with p.open('rb') as f:
        actual = hashlib.file_digest(f, 'sha256').hexdigest()
    assert actual == r['sha256'], str(p)
print('All source, checkpoint, result and dataset hashes match.')
'@ | .\.venv\Scripts\python.exe -

.\.venv\Scripts\python.exe -m unittest tests.test_vs_mt_adlif tests.test_vs_mt_ssc_runner
.\.venv\Scripts\python.exe runner_vs_mt_ssc.py --datasets SSC --seeds 42 123 456 --dry-run
```

Only the user starts training:

```powershell
.\.venv\Scripts\python.exe runner_vs_mt_ssc.py --datasets SSC --seeds 42 123 456
```

No original MT training will be scheduled. This starts three new VS-MT seeds
from random weights and fresh optimizers. Rerun the same command to resume
compatible interrupted seeds or skip completions. Do not run a second launcher
into the same output directory.

Keep the environment, device information and resolved configs with the runs;
different hardware/software can produce different results despite matching
seeds. See [the experiment guide](../experiments/vs-mt-ssc.md) for the model
definition, reporting and cost-measurement behavior. Preserve the same relative
`results/experiments/vs_mt_ssc_v1/` layout when transferring results back.
